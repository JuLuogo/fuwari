博客部署在 Cloudflare Workers 上，域名走 Cloudflare 的免费套餐。上线之后我一直有个疑问：**从国内访问，到底是"能用"还是"不能用"？**

在自己电脑上 `ping` 一下意义不大——我人在河北，测出来的只是"我这一个点"的延迟，广东、四川、新疆的网友体验可能完全不同。要看全貌，必须用**多节点测速**。

这篇文章就是一次完整的体检记录，顺便讲讲这些数字应该怎么读。

> [!NOTE]
> 本站是 Astro 静态站点，跑在 Cloudflare Workers 上（免费套餐，没有买 Argo 或任何加速服务），域名 `juluo.work` 由 Cloudflare 托管 DNS。所有数据都是 2026-10-05 晚实测。

## 为什么不用单点 Ping

单点 Ping 有三个坑：

1. **只有一条线路**：你家宽带是联通，就只能看到联通的情况，电信、移动用户的体验完全不知道。
2. **受本机网络影响大**：本地路由器、运营商出口 QoS 都会干扰结果。
3. **ICMP 经常被限速**：很多 CDN 对 ICMP 请求做了限速或降级处理，Ping 出来的数字不代表真实网页加载速度。

所以我用的是 **[tcptest.cn](https://www.tcptest.cn/)** 的在线多节点测试。选它的理由很实际：免费、不用注册、国内节点有 156 个（覆盖三大运营商 + 港澳台/海外），结果直接给一张地图加一张按运营商/大区分组的表格，截图就能当证据用。

## 第一轮：Ping（ICMP 延迟）

先看最基础的 ICMP Ping：

![tcptest.cn 的在线 Ping 测试结果，156 个节点参与，平均 233ms](/assets/images/posts/blog-ping-tcping-checkup/01-ping-result.webp)

数据摘出来：

| 维度 | 最快 | 最慢 | 平均 |
| --- | --- | --- | --- |
| 全部节点 | 中国香港 <1ms | 新疆阿勒泰 294ms | **233ms** |
| 中国电信 | 福建泉州 196ms | 新疆阿勒泰 294ms | 243ms |
| 中国联通 | 安徽六安 185ms | 浙江湖州 287ms | 230ms |
| 中国移动 | 中国天津 176ms | 甘肃庆阳 279ms | 229ms |
| 华东地区 | 安徽六安 185ms | 浙江湖州 287ms | 220ms |
| 西南地区 | 四川成都 209ms | 西藏拉萨 285ms | 236ms |
| 西北地区 | 甘肃武威 221ms | 新疆阿勒泰 294ms | 253ms |

几个观察：

- **国内平均 233ms**，最好的节点（天津移动）176ms，这个量级属于"能打开，但不算快"。
- **三大运营商差别不大**（229~243ms），说明瓶颈不在某一个运营商的互联互通，而是**流量要出国再回来**。
- **港澳台 <1ms**——这不是黑科技，是因为 tcptest 的"中国香港"检测点本身就在 Cloudflare 的同一批机房附近，等于同机房互 ping。看到这种数字不用激动，它不代表真实用户。
- 表格底部有一行 **"响应超时 14"**，也就是 156 个节点里有 14 个完全没响应。ICMP 超时很常见（对方禁 Ping 或链路丢包），**不能直接理解为"14 个省份打不开网站"**。

## 第二轮：Tcping（TCP 443 端口）

ICMP 会被限速，真正决定网页能不能打开的是 **TCP 握手**。Tcping 测的就是到 `blog.juluo.work:443` 建立 TCP 连接要多久：

![tcptest.cn 的在线 Tcping 测试结果，平均 357ms，最慢 2273ms](/assets/images/posts/blog-ping-tcping-checkup/02-tcping-result.webp)

这轮数据明显比 Ping 难看：

| 维度 | 最快 | 最慢 | 平均 |
| --- | --- | --- | --- |
| 全部节点 | 中国香港 1ms | 辽宁盘锦 2273ms | **357ms** |
| 中国电信 | 河南郑州 171ms | 辽宁盘锦 2273ms | 405ms |
| 中国联通 | 广东中山 180ms | 河北唐山 1309ms | 306ms |
| 中国移动 | 安徽淮北 147ms | 陕西西安 1283ms | 354ms |
| 东北地区 | 吉林长春 177ms | 辽宁盘锦 2273ms | 585ms |
| 西北地区 | 青海西宁 213ms | 陕西西安 1283ms | 467ms |

**为什么 Tcping 比 Ping 慢这么多？**

- TCP 握手是三次往返（SYN → SYN-ACK → ACK），而 ICMP 只有一次往返，**协议开销天然放大 2~3 倍**。
- 表格里那些 1000ms+ 的"最慢"值，通常不是稳定延迟，而是**首次连接要绕路 + 排队**的结果：Cloudflare 的免费套餐不做国内优化，流量可能绕到香港、日本、圣何塞，再回到目标机房。
- 有几个节点（辽宁盘锦 2273ms）明显是**长尾**，这种值对单个用户就是"打开网页要等两秒"，体验很差。

结论很直白：**Cloudflare 免费套餐在国内的真实体验是 200~400ms 的握手延迟**，首次访问会有肉眼可感知的等待，热连接（HTTP/2、HTTP/3 复用）之后会好一些。

## 第三轮：DNS 解析到了哪

再看一眼域名解析——这决定了你的流量被送到哪个 Cloudflare 机房：

![tcptest.cn 的 DNS 查询结果，解析到两个 Cloudflare Anycast IP](/assets/images/posts/blog-ping-tcping-checkup/03-dns-query.webp)

结果：

- `104.21.6.247` —— 50.97%
- `172.67.135.130` —— 48.39%
- `172.64.80.1` —— 0.65%

这三个 IP 都属于 Cloudflare 的 **Anycast 网段**：同一个 IP 在全球几百个机房同时宣告，用户的流量会被 BGP 路由到"网络意义上最近"的机房。

> [!TIP]
> 想知道某个 IP 是不是 Cloudflare，可以直接看它是不是 `104.16.0.0/13`、`172.64.0.0/13`、`104.21.0.0/16` 这类段，或者用 `curl -s https://ip.sb` 之类的服务反查。

**关键点**：Anycast 的"最近"是按 BGP 路由跳数算的，不是按物理距离。所以河北的用户完全可能被送到香港或新加坡的机房——这就解释了为什么国内各地延迟都在 200ms 以上却比较均匀。

## 这些数字到底该怎么读

1. **平均值没有意义，看分位数**。表格给的是"最快/最慢/平均"，真实体验更接近"平均偏慢"那一档：平均值 233ms 的 Ping，意味着相当一部分节点在 250ms 以上。
2. **超时数量要结合场景看**。14 个节点 ICMP 超时，但 TCP 只超时 1 个——说明链路本身是通的，只是 ICMP 被丢/被限速。
3. **Ping 快 ≠ 网站快**。网页加载还要算 TLS 握手、首字节时间（TTFB）、资源并发下载。Ping 233ms 的站点，页面"看起来能打开"要 1~2 秒。
4. **港澳台/海外 <1ms 的数据要警惕**。那是检测点位置特殊，不代表你的读者在香港。

## 那要不要为了国内速度折腾

看你的读者在哪：

- **读者主要在国内**：Cloudflare 免费套餐的 200~400ms 只是"能用"。想更快，方向有三个——Cloudflare 优选 IP（自选回源 IP）、Cloudflare SaaS 回源到国内/香港的服务器、或者干脆换国内 CDN（需要备案）。
- **读者主要是自己和海外朋友**：免费套餐完全够用，别折腾。

我目前的结论是：**先不折腾**。博客的定位是记录和分享，200ms 的延迟换来的是零服务器成本、全球 Anycast 和免运维，这个交换我认为划算。等哪天有真实读者抱怨慢，再考虑优选 IP 那套方案（到时候会单独写一篇，把备案、优选、SaaS 回源的取舍讲清楚）。

## 小结

- 用 tcptest.cn 这类多节点工具，10 分钟就能把"全国访问体验"量化出来，比本机 ping 靠谱得多。
- 本次实测：ICMP 平均 233ms、TCP 443 平均 357ms，最慢节点超过 2 秒。
- TCP 延迟比 ICMP 高 2~3 倍是正常现象，别把 Tcping 的高值当成"服务器挂了"。
- Anycast 决定了国内流量大概率绕道，这是 Cloudflare 免费套餐的固有特性，不是配置问题。
